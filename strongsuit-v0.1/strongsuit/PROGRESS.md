15. `favicon.svg` referenced by index.html is the old/default; design a Coachwright "C-collar" favicon in the branding pass.
16. **Sync is only half-connected end to end.** `lib/sync.ts`'s E2EE crypto is solid and tested; `WiFiSyncDialog`'s Electron-hosted local server can receive `/sync/push`, but nothing on the *Companion* (client-facing) side actually calls it yet — the Companion HTML template has no "sync over WiFi" button POSTing to the discovered coach IP. Today the real, fully-working path is manual `.cwsync` file export/import (Studio Link page) or the Companion's existing `.ssdata` file-based return path — both zero-server and complete. Closing the WiFi loop needs: (a) a small vanilla-JS fetch call added to `companion/template.html`, (b) a "which client is this" pairing step. The standalone `sync-server/` (Express+SQLite) prototype is a separate, unwired, self-host-only cloud relay option — not connected to anything by default, and its API key defaults to a hardcoded string (`'default-coachwright-key'`) that MUST be overridden if anyone actually deploys it; document that loudly before ever recommending it to a buyer.
17. **Android is scaffolded, not verified.** `android/` is a real Capacitor-generated project (not a stub), but no Android SDK/Gradle/emulator exists in any environment this has been built in — it has never been compiled, launched, or tested on a device. Treat as "next step ready," not "done." See `docs/ANDROID_STRATEGY.md`.
18. **Windows/Electron is verified statically, not by a live GUI launch.** `electron/main.ts`+`preload.ts` compile clean; `dist/index.html` uses `file://`-safe relative asset paths; `contextIsolation`/`nodeIntegration` are set securely; the Electron binary itself runs (`--version` succeeds). A live window launch (`npm run dev:electron`) and a packaged installer (`npm run build:electron`, NSIS) have **not** been executed in this sandboxed environment — do that once, interactively, before calling Phase 9 done.
19. `sync-server/` (the standalone cloud relay) has its own `node_modules` and a `coachwright.db` SQLite file already committed to disk from earlier testing — harmless, but don't accidentally ship that populated `.db` file if this ever gets packaged for distribution.
20. Several components used undefined Tailwind classes (`bg-brand`, `text-brand-500`, `hover:bg-ember-50`, `dark:hover:bg-ember-900/20`) that silently no-op instead of erroring — found and fixed in `MessagesTab`, `SyncCenterPage`, `MetricsTab` (×2), `DashboardPage`, `SettingsPage` during S10's audit. **If a class doesn't visibly do anything, check it's a real token in `tailwind.config.js` before assuming the CSS is just subtle** — Tailwind won't warn you.
21. `sessionsRemaining` (used by the `package-low-sessions` automation rule) is an **estimate** — `purchased session-credit total − all-time logged sessions` — not a true decrementing pack ledger (no such first-class concept exists yet). Fine for a nudge; don't present it to a buyer as exact.
